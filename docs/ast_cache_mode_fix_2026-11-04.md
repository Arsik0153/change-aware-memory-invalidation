# Исправление AST-кэша при смене типа Git-записи

Исправлен воспроизводимый дефект: один и тот же Git blob мог переиспользоваться
как обычный Python-файл и как неподдерживаемая символьная ссылка. Кэш модуля
учитывал object ID, версию Python/индексатора, путь и имя модуля, но не текущие
ограничения snapshot.

## Наблюдаемый сбой

Синтетическая Git-история сохраняет байты `def f(): pass` и blob ID, меняя только
mode: обычный файл → symlink → обычный файл. Ссылки не разрешаются и не исполняются;
исследование должно скрыть запись при неподдерживаемом источнике и восстановить
после возвращения обычного файла.

До исправления регрессионный тест упал для всех трёх проверяющих policies:

- symbol_validate: доступность `[true, true]` вместо `[false, true]` — старый AST
  маскировал новое ограничение, поэтому проверка symlink пропускалась.
- file_validate и all_validate: `[false, false]` вместо `[false, true]` — модуль
  с прежним ограничением ошибочно переиспользовался после восстановления файла.

В обоих случаях причина находится до оценки истинности: неверно переиспользован
результат анализа источника. Это отдельный механизм ошибки, не скрытая зависимость.

## Исправление и совместимость

`build_index` теперь обрабатывает `blob.limitation` до обращения к AST-кэшу.
Ограниченный blob не получает ранее разобранный модуль и не записывает ограничение
в кэш обычных модулей. Успешный разбор читаемого Git blob остаётся кешируемым.
Аналогичная проверка выполнена при изменении допустимого размера файла:
кэшированный и свежий индекс совпадают при чередовании readable/file_too_large.

INDEX_VERSION повышен с 2 до 3, VALIDATOR_VERSION — с 3 до 4. Это отделяет новые
индексы и validation cache keys от прежних. Старые файлы кэша не удаляются.
Отдельный реальный запуск all_validate сначала сохранил ошибочный результат
старой реализации в кэш; после исправления тот же config дал `[false, true]`,
а ни один прежний validation result не был переиспользован.

## Свидетельства

`same-blob-symlink-red.log` содержит три ожидаемых падения до правки;
`same-blob-symlink-green-v2.log` — 132 прошедших профильных tests после неё.
Ruff и mypy прошли. Журналы находятся в `reports/research-20261104/`.
`same-blob-cache-before-after.json` связывает обе реализации хешами и фиксирует
проверку дискового кэша. Полные локальные runs: `runs/same-blob-cache-20261104-v1/`.

Это проверка на специально построенной Git-истории, не оценка частоты таких
переходов в реальных репозиториях. Полный suite на новом коде выполняется отдельно;
прежние 1115 tests относятся к состоянию до данного исправления.
