# Применимость структурного binding gate к реальным parent-модулям

Текущий консервативный binding gate проходит только у 30 из 504 подготовленных
структурных кандидатов. Остальные 474 отклоняются уже на этом необходимом условии.
Это измерение применимости технического ограничения, а не доля истинных claims
и не оценка качества CAMI. Даже 30 прошедших записей не получили разрешения на
closure: текущий addendum допускает только synthetic fixtures.

План закреплён в b519e9a до реализации. Проверка прочитала только 63 parent snapshots,
не исполняла код репозиториев, не читала child sources и не запускала policies.
Она вызывала только `_binding_check` на AST целого subject-модуля; `_close` и
`prepare_structural_closure` не вызывались. Provenance flags, receipts, labels
и человеческие ответы не создавались и не изменялись.

## Результат по заранее определённому набору

| Репозиторий | Структурных кандидатов | Проходит только binding gate | Отклонено этим gate |
|---|---:|---:|---:|
| Click | 160 | 2 | 158 |
| Requests | 176 | 27 | 149 |
| pytest | 168 | 1 | 167 |
| Всего | 504 | 30 | 474 |

504 записи — восемь структурных кандидатов в каждой из 63 parent-групп,
включая подготовку replay. Это не знаменатель основного 600-item child набора.
Они относятся к 345 различным сочетаниям repository/parent/path; 23 таких модуля
прошли gate, 322 отклонены. Claims одного модуля не являются независимыми пробами.

Первый зафиксированный отказ на уровне claims: indirect namespace write — 228,
dynamic namespace — 167, cross-scope/walrus — 38, unsupported/conditional module
binding — 28, executable module/header expression — 13. Это первые причины
по порядку обхода, не полные множества всех нарушений и не независимые категории
свойств программ. Нечитаемых или синтаксически непригодных subject-модулей нет.

## Последствие для дизайна исследования

Этот результат показывает, что успех fixture closure нельзя механически
перенести на подготовленные реальные данные. Даже получение независимых
truth labels само по себе не устранит эти технические препятствия: истина claim
и достаточность provenance — разные требования.

Для следующего варианта критерия необходимо отдельно обосновать, какие ограничения
нужны точному синтаксическому predicate, а какие относятся только к runtime binding.
Нельзя просто снять проверки после просмотра данной таблицы и объявить все claims
закрытыми. Изменённый критерий потребует отдельного доэкспериментального протокола,
проверок неоднозначности/перепривязки и независимого review; исходный вариант
должен остаться доступен для сравнения.

Если сохраняется текущий критерий, следует ожидать небольшой применимой части
набора и консервативных fallback у остальных. Это ограничение применимости,
которое нужно показать в диссертации даже при положительных результатах на fixtures.
Здесь число полных допустимых real closures равно нулю по правилу authority;
30 — лишь верхняя граница до остальных технических условий и review.

## Проверка и воспроизведение

112 профильных tests прошли. Снимки исходников до/после совпали; hashes входов,
retained source blobs и готового набора подготовки проверены. Сырые источники:
`runs/binding-gate-20261104-v1/sources/`; компактные протокол, строки наблюдений,
summary и manifest: `reports/research-20261104/binding-gate-v1/`.

```bash
.venv/bin/python -m scripts.check_binding_gate \
  --out runs/binding-gate-NEW
```

Требуются локальные parent repositories и candidates по путям frozen plan.
Этот диагностический скрипт не заменяет independent review и не предоставляет
нового разрешения на реальную closure или held-out execution.
