# Точная вероятность доступности bootstrap interval

## Предварительный план механистического анализа

Это post-pilot sensitivity analysis после уже выполненного исследования 600
синтетических datasets. Он не является новым preregistration исходного pilot и
не проверяет эффективность CAMI на реальных репозиториях. План и сетка фиксируются
до вычисления таблиц: examples/bootstrap_study/availability_protocol.json.

Гипотеза: при текущем правиле отказа на любом пустом resample доступность CI
не возрастает с числом повторов B. Число кластеров K и вероятность активности q
сохраняются такими же, как в шести исходных сценариях. B∈{50,100,500,2000,10000}.
Метод построения CI и исходные результаты не меняются.

В этом генераторе Z — число неактивных кластеров — имеет распределение
Binomial(K,1−q). При фиксированном Z=z вероятность пустого resample равна
r(z)=(z/K)^K, поскольку все K выбранных кластеров должны попасть в пустое множество.
Для z<K вероятность доступного CI после B независимых resamples равна
(1−r(z))^B. При z=K исходная sample estimate уже не определена.

Искомая безусловная вероятность:

```
P(CI available) = sum[z=0..K-1] C(K,z) (1-q)^z q^(K-z) (1-(z/K)^K)^B.
P(sample denominator zero) = (1-q)^K.
```

Каждое слагаемое не возрастает по B. Для 0<q<1 некоторые слагаемые строго убывают;
при B→∞ остаётся только z=0 с массой q^K. Это свойство данного правила отказа и
генератора, а не рекомендация уменьшить B и не утверждение о достаточной coverage.
При меньшем B неопределённость оценки quantiles может возрастать; в этом анализе
их качество не оценивается.

Дополнительно рассчитывается ожидаемое число реально начатых resample iterations.
Для z=K оно равно 0; для r=0 — B; иначе (1−(1−r)^B)/r. Сюда входит неудачный
resample, на котором цикл остановился. Это число итераций, не latency или расход CPU.

Проверка формул: точный перебор всех activity assignments и resample sequences
для малых K,B без вызова bootstrap CAMI; граничные случаи q=1; монотонность по B;
сумма масс available/zero sample/zero resample равна единице. На сохранённых pilot
данных отдельно сопоставляются observed availability, условное математическое
ожидание по их фактическим Z и безусловное ожидание генератора. Эти два ожидания
нельзя смешивать. Новые random datasets для выбора красивого результата не создаются.

Результаты будут внесены после вычисления и независимой проверки.
