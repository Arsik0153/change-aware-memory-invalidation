# Точная вероятность доступности bootstrap interval

## Предварительный план механистического анализа

Это post-pilot sensitivity analysis после уже выполненного исследования 600
синтетических datasets. Он не является новым preregistration исходного pilot и
не проверяет эффективность CAMI на реальных репозиториях. План и сетка фиксируются
до вычисления таблиц: examples/bootstrap_study/availability_protocol.json.

Гипотеза: при текущем правиле отказа на любом пустом resample доступность CI
не возрастает с числом повторов B. Число кластеров K и вероятность активности q
сохраняются такими же, как в шести исходных сценариях. B∈{50,100,500,2000,10000}.
Метод построения CI и исходные результаты не меняются.

В этом генераторе Z — число неактивных кластеров — имеет распределение
Binomial(K,1−q). При фиксированном Z=z вероятность пустого resample равна
r(z)=(z/K)^K, поскольку все K выбранных кластеров должны попасть в пустое множество.
Для z<K вероятность доступного CI после B независимых resamples равна
(1−r(z))^B. При z=K исходная sample estimate уже не определена.

Искомая безусловная вероятность:

```
P(CI available) = sum[z=0..K-1] C(K,z) (1-q)^z q^(K-z) (1-(z/K)^K)^B.
P(sample denominator zero) = (1-q)^K.
```

Каждое слагаемое не возрастает по B. Для 0<q<1 некоторые слагаемые строго убывают;
при B→∞ остаётся только z=0 с массой q^K. Это свойство данного правила отказа и
генератора, а не рекомендация уменьшить B и не утверждение о достаточной coverage.
При меньшем B неопределённость оценки quantiles может возрастать; в этом анализе
их качество не оценивается.

Дополнительно рассчитывается ожидаемое число реально начатых resample iterations.
Для z=K оно равно 0; для r=0 — B; иначе (1−(1−r)^B)/r. Сюда входит неудачный
resample, на котором цикл остановился. Это число итераций, не latency или расход CPU.

Проверка формул: точный перебор всех activity assignments и resample sequences
для малых K,B без вызова bootstrap CAMI; граничные случаи q=1; монотонность по B;
сумма масс available/zero sample/zero resample равна единице. На сохранённых pilot
данных отдельно сопоставляются observed availability, условное математическое
ожидание по их фактическим Z и безусловное ожидание генератора. Эти два ожидания
нельзя смешивать. Новые random datasets для выбора красивого результата не создаются.

## Расширение на разные знаменатели политик

Следующий анализ рассматривает фиксированные множества кластеров с ненулевыми
знаменателями у каждой политики. Это отдельное post-pilot расширение, а не
изменение исходного генератора или bootstrap estimator. План:
`examples/bootstrap_study/paired_support_protocol.json`. В нём 15 заранее
описанных конфигураций поддержки и B∈{1,10,50,2000}; новых случайных datasets нет.

Пусть K≥2 — число кластеров; L и R — числа кластеров с положительным знаменателем
слева и справа; J — число кластеров, положительных с обеих сторон. Допустимы
max(0,L+R−K)≤J≤min(L,R). Тогда K−L−R+J кластеров пусты с обеих сторон.

При K независимых равномерных выборах с возвращением события «левый denominator
нулевой» и «правый denominator нулевой» могут пересекаться. По включению-исключению
вероятность недопустимого resample равна:

```text
r = ((K-L)/K)^K + ((K-R)/K)^K - ((K-L-R+J)/K)^K.
```

Если L=0 или R=0, исходная оценка не определена и bootstrap не начинается.
Иначе вероятность доступного CI при существующем правиле отказа равна
`(1-r)^B`. Это вероятность по распределению bootstrap draws, условная на
данные support sets; у уже выбранного seed результат детерминирован.
При L=R=J выражение сводится к ранее рассмотренному общему denominator.

Из формулы следует проверяемое свойство: при фиксированных K,L,R увеличение J
не уменьшает availability. При J=0 интервал всё ещё может быть доступен:
один resample способен содержать разные кластеры, поддерживающие разные стороны.
Само отсутствие jointly-positive cluster не является достаточным основанием
для отказа. Availability по-прежнему ничего не утверждает о coverage.

План проверки включает полный перебор support masks и resamples для K=2..4,
перебор коротких последовательностей с подачей заданных draws производственному
bootstrap, совпадение с прежней общей формулой, границы и монотонность.
Вероятность одного resample вычисляется точной рациональной арифметикой;
конечные степени B — Decimal с precision100. Малые ненулевые значения сохраняются
как decimal strings, чтобы float underflow не превратил их в математический ноль.
Независимый reviewer должен повторно проверить все 60 строк после расчёта.

Пример при одинаковых marginal counts K=20, L=R=8 и B=2000:

| Пересечение J | Условная вероятность доступного CI |
| --- | ---: |
| 8, полное | 92,948510% |
| 4, частичное | 86,395923% |
| 0, отсутствует | 86,394024% |

Это вероятности по bootstrap draws при фиксированных support sets. Они не равны
безусловной вероятности по Bernoulli-генератору прежнего pilot и не являются
наблюдаемыми долями из нового Monte Carlo эксперимента. Одинаковые L и R могут
давать разную availability, поэтому ранее добавленный joint_nonzero_clusters
содержит существенную диагностическую информацию.

Небольшой точный пример: K=2, L=R=1, J=0. Один кластер поддерживает только левую
сторону, другой — только правую. Resample из двух draws имеет оба знаменателя
положительными в двух из четырёх вариантов. Для двух независимых resamples
вероятность доступного интервала равна (1/2)^2=1/4, хотя J=0. Для B=2000 она
приблизительно 8,709809816×10^-603: Decimal serialization сохраняет ненулевое
значение, которое обычное преобразование в binary float округлило бы до нуля.

## Какие метрики CAMI имеют разную поддержку знаменателя

Общая формула для парной поддержки не означает, что у всех метрик CAMI
знаменатели различаются между политиками. При сравнении одного cohort с общей
разметкой и одинаковой кластеризацией множества истинных `supported` и
`contradicted` внутри каждого кластера фиксированы.

Обозначим их S и C, доступные записи — A. Пусть P содержит только бинарно
размеченные записи с текущей подтверждённой инвалидацией: финальный state stale
или retired, текущий checked revision и совпадающий contradicted verdict.
Записи с uncertain label не входят в P для precision/recall/F1.

| Метрика | Знаменатель | Может ли поддержка отличаться между политиками |
| --- | --- | --- |
| stale_exposure | размер C | Нет, при общем cohort и labels |
| valid_retention | размер S | Нет |
| valid_withholding | размер S | Нет |
| selection_recall | размер C | Нет, когда метрика применима |
| false_invalidation | размер S | Нет, когда метрика применима |
| invalidation_recall | размер C, поскольку TP+FN=размер C | Нет, когда метрика применима |
| available_contamination | размер A∩(S∪C) | Да, зависит от доступности записей |
| invalidation_precision | размер P | Да, зависит от подтверждённых инвалидаций |
| invalidation_f1 | размер P + размер C | Да, но только в кластерах без contradicted labels |
| uncertain_available | Нет, это количество | Rate CI для этой метрики не рассчитывается |

Для F1 равенство следует из `2TP+FP+FN = (TP+FP)+(TP+FN)`.
Если в кластере C непусто, знаменатель F1 положителен при любом P. Когда C пусто,
наличие положительного знаменателя зависит от ложноположительных инвалидаций.
Разные значения положительных знаменателей не обязательно означают разную
поддержку: для доступности resample важно, где знаменатель равен нулю.
Если support sets совпадают, достаточно прежней односторонней формулы даже
при разных положительных величинах знаменателя.

Основные exposure и retention относятся к общим label denominators. Поэтому
эффект пересечения J из нового анализа не следует представлять как отдельный
фактор их сравнительной availability при корректно спаренном cohort. Он нужен
для метрик с policy-dependent support и для проверки согласованности отчёта.
Наличие числовых counts ещё не делает сравнение допустимым.

`_rate` сохраняет raw numerator и denominator даже при `not_applicable`, но
возвращает value=null. Aggregate проверяет reason до bootstrap. Например,
подтверждённая invalidation precision не становится применимой к `clear_all`
только потому, что scorer способен посчитать некоторые промежуточные числа.
Аналогично, raw count `uncertain_available` не имеет rate denominator.
Для replay действует отдельный запрет population CI до рассмотрения support;
теоретическая доступность bootstrap не снимает этот запрет.
