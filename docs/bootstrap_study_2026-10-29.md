# Development исследование paired cluster bootstrap

## Протокол до запуска

Цель — проверить ограничения интервалов существующего оценивателя CAMI на
синтетических данных с аналитически известной истиной. Production алгоритм не
меняется. Результат не проверяет качество CAMI, не использует реальные labels и
не заменяет основной эксперимент.

Структура описания следует ADEMP: цель, генератор данных, оцениваемая величина,
метод и показатели. Источник: Morris, White, Crowther (2019),
[Using simulation studies to evaluate statistical methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC6492164/).

Машинный протокол — `examples/bootstrap_study/protocol.json`. Он фиксируется
commit до первого запуска исследования. Шесть сценариев по 100 независимых
синтетических datasets. Количество независимых кластеров K ∈ {5, 20, 50};
вероятность активного кластера q ∈ {1, 0.1}. Это небольшой development pilot,
а не высокоточная калибровка номинального 95% покрытия.

Для каждого кластера независимо выбираются активность A~Bernoulli(q), размер
N∈{5,50} с равными вероятностями и p∈{0.1,0.3} с равными вероятностями. При A=0
обе политики имеют counts (0,0). При A=1 для каждого из N элементов генерируется
общий U~Uniform(0,1). Left событие U<p, right событие U<0.5p. Поэтому сравниваемые
политики положительно зависимы внутри пары, а элементы имеют общий кластерный p.
Разные кластеры независимы. Размер, активность и p независимы.

Оцениваемая величина — разность популяционных micro rates:

```
E[left numerator]/E[denominator] − E[right numerator]/E[denominator]
= E[p] − 0.5 E[p] = 0.1.
```

Истина выведена из генератора, не оценена CAMI и не получена из Monte Carlo.
Нулевой знаменатель у целого dataset делает sample estimate недоступной,
но не отменяет существования популяционного параметра при q>0.

Метод — неизменённый `paired_cluster_bootstrap`, 2000 повторов. Seed генерации
и seed bootstrap раздельны и выводятся из master seed, номера сценария и trial.
Исключения исполнения прекращают запуск, а недоступные интервалы записываются
как результаты с причиной. Все datasets и результаты сохраняются в JSONL.

Основные показатели по сценарию:

- Доля доступных интервалов среди всех trials.
- Coverage среди trials с доступным интервалом; null, если таких trials нет.
- Доля trials, где интервал одновременно доступен и покрывает истину.
- Количество причин недоступности, средняя ширина доступных интервалов.
- Bias среди trials с определённой sample estimate, отдельно от coverage.
- Верхняя граница стандартной ошибки Monte Carlo долей, 0.5/sqrt(n), где n
  равен соответствующему знаменателю. Это не доверительный интервал.

Неопределённые resamples не выбрасываются молча. Для dataset с Z пустыми
кластерами вероятность полностью пустого resample равна (Z/K)^K. Вероятность
хотя бы одного такого resample за B независимых повторов равна
1−[1−(Z/K)^K]^B. Записываем эту независимую аналитическую проверку механизма
отказа рядом с фактическим исходом. Она применима здесь, где знаменатели политик
совпадают; не переносится автоматически на любые другие metrics.

Результат фиксируется независимо от направления эффекта. Не подбираем seed,
сценарии или число trials по полученным значениям. При ошибке runner сохраняем
след неудачного запуска и создаём новый output после исправления. Полного
эмпирического распределения реальных репозиториев этот генератор не описывает.

## Результат первого запуска

Протокол зафиксирован в `db63bff`, runner в `d3d133d`. Выполнены все 600 trials;
неудачных исполнений не было. Недоступный интервал считается исходом метода,
а не ошибкой runner. При первом пустом resample метод прекращает bootstrap;
2000 — заданный максимум, не утверждение о числе реально выполненных повторов.

| Сценарий | Доступные интервалы | Покрывают истину среди доступных | Доступен и покрывает среди всех | Не определена sample estimate |
| --- | ---: | ---: | ---: | ---: |
| dense-k5 | 100/100 | 84/100 | 84/100 | 0 |
| dense-k20 | 100/100 | 97/100 | 97/100 | 0 |
| dense-k50 | 100/100 | 98/100 | 98/100 | 0 |
| sparse-k5 | 0/100 | не определено | 0/100 | 60 |
| sparse-k20 | 1/100 | 1/1 | 1/100 | 13 |
| sparse-k50 | 20/100 | 19/20 | 19/100 | 0 |

Для sparse-k5, sparse-k20, sparse-k50 независимая формула вероятности отказа,
применённая к сохранённым datasets, даёт ожидаемые количества недоступных интервалов
100.000, 99.792 и 78.681. Наблюдались соответственно 100, 99 и 80. Это объясняет
механизм наблюдения; отдельный goodness-of-fit test не выполнялся.

При K=5 в dense сценарии наблюдаемое покрытие ниже номинального. Это предупреждение
о малых выборках в данном генераторе, не универсальный порог достаточного K.
При sparse-k20 значение 1/1 почти ничего не говорит о калибровке интервала.
При sparse-k50 красивое условное 19/20 скрывает 80 недоступных интервалов из 100.
Поэтому coverage без availability был бы неполным описанием результата.

Для 100 trials верхняя граница MCSE доли равна 0.05. Для условного покрытия
sparse-k20 она равна 0.5, sparse-k50 — около 0.112. Это стандартные ошибки
Monte Carlo, не ширина доверительного интервала и не измерение неопределённости
реального исследовательского эффекта. Результат является development pilot.

Оцениватель и протокол основного исследования не изменены. Отказ после пустого
resample — существующее явное правило, не доказанная ошибка. Молчаливое удаление
таких resamples означало бы другое условное распределение. Альтернативу можно
изучать только отдельным заранее описанным development сравнением.

## Воспроизведение и проверка

Из корня репозитория с установленным окружением:

```sh
.venv/bin/python scripts/bootstrap_study.py --out reports/bootstrap-reproduction-001
.venv/bin/python scripts/report_bootstrap_study.py \
  --input reports/bootstrap-reproduction-001 --out reports/bootstrap-report-001
.venv/bin/pytest -q tests/test_bootstrap_study.py tests/test_bootstrap_contract.py \
  tests/test_evaluation.py tests/test_aggregate.py
```

Нужны новые output directories. Runner не перезаписывает существующие результаты.
Источник первого запуска: `reports/research-20261029/bootstrap-study-v1/`.
`manifest.json` фиксирует protocol hash, hashes runner/evaluator/lockfile, Git HEAD,
Python и NumPy. Это не полная аттестация ОС или всех импортированных исходников.
`trials.jsonl` содержит counts, bootstrap seed, interval и coverage каждого trial.
`summary.json` хранит показатели и их знаменатели. `protocol.json` — сохранённые
байты входного протокола.

Report script заново проверяет hashes, полноту trial IDs, counters, estimates,
coverage и его агрегированные знаменатели. Он не пересчитывает сами bootstrap
quantiles. Проверка намеренно подменённой summary с обновлённым hash подтверждает,
что согласованность с raw trials проверяется сверх целостности файлов.

Графики для научного текста:
`reports/research-20261029/bootstrap-study-report-v1/coverage.png` и `coverage.svg`.
График указывает числители и знаменатели; uncertainty отдельно описана выше.

Итоговый профильный набор: **43 passed**. Ruff всего проекта и mypy production
кода прошли. Полный suite на этом этапе не повторялся: production код не менялся,
новые runner и report проверены профильными tests и реальным исполнением.

Независимый review `gpt-6.1-sol` проверил математику, выполнил 10 исходных tests
runner и перепроверил hashes и summary counts по 600 raw trials. Блокирующих
замечаний нет. Позже добавленный report script проверен родителем, включая
негативный тест подмены summary. Он не прошёл отдельного независимого review.

## Следующий шаг

Результат показывает, что «20 кластеров» без информации об активных кластерах
не гарантирует доступность интервала. Перед основным экспериментом нужны
описание количества кластеров с ненулевыми знаменателями для каждой метрики
и явный отчёт причин недоступности. Следует проверить, достаточно ли текущий
aggregate report раскрывает эти числа; при пробеле добавить диагностику,
сохранив estimator и правила допуска неизменными.

## Усиленная независимая проверка отчёта

Первый reporter пересчитывал availability/coverage counts и sample estimates,
но не сверял bias, mean width, MCSE bounds и expected unavailable count. На отдельной
намеренно испорченной synthetic fixture воспроизведён пропуск: bias=999.0 принимался
после обновления hash summary. Исходные 600 trials и их summary не изменялись.

Теперь reporter независимо от генератора и CAMI estimator выводит истину из
параметров генератора и пересчитывает все поля summary по raw trials. Проверяются
полная совокупность cluster IDs, целочисленные paired counts, общие denominators,
nested outcomes, допустимость наблюдаемых категорий при заданных вероятностях,
число пустых кластеров, аналитическая вероятность пустого resample, размеры
интервала и доступные denominator-support diagnostics. Для исторического v1
отсутствующие optional support fields допустимы; они не подменяются выдуманными.

Независимый reviewer нашёл два крайних случая в новом validator: различие
`numpy.mean` и `math.fsum` на несколько ulps у границы интервала; невозможные counts
при вероятностях 0/1. Добавлены regression tests и исправления. Truth сверяется
с независимой формулой при rel_tol=1e-12, abs_tol=1e-15; coverage затем считается
по тому же сохранённому float, который прошёл эту проверку. Это предотвращает
ложный отказ корректного результата на точной границе. Для каждого активного
cluster требуется хотя бы одно объявленное p, при котором все наблюдённые
категории nested Bernoulli имеют положительную вероятность.

Итог: 37 focused tests, ruff и mypy passed. Испорченный bias отвергается до создания
output. Все исходные 600 trials успешно перепроверены; существующие численные
выводы сохранены. Evidence: `reports/research-20261029/bootstrap-study-revalidated-v3/`.
`validation.json` фиксирует hash reporter, области проверки и допуски.

Эта проверка не регенерирует random streams и не пересчитывает bootstrap quantiles.
Проверка точного равенства estimator outputs на сохранённых 600 datasets описана
в предыдущем этапе denominator diagnostics. Hash подтверждает соответствие файлов
внутри пакета, но сам по себе не доказывает корректность расчётов или происхождение
данных; именно поэтому численные показатели пересчитываются отдельно.
