# Символическая проверка условий периодического аудита

Шесть условий перехода проверены для произвольного положительного целого K:
решатель не нашёл контрпримеров к их формализации. Для каждого условия отдельно
найдено решение предпосылок, чтобы исключить доказательство из противоречивых
условий. Сохранены SMT-LIB формулы, ответы, шесть proof objects и шесть специально
заданных примеров/контрпримеров.

Это проверка вручную формализованного перехода и его инвариантов. Она дополняет
[аргумент о доступности](availability_invariants_2026-11-04_ru.md), но не является
формальной верификацией всей production-реализации или корректности probes.

## Формализация

Использованы неограниченные математические Int и Bool в QF_LIA. K≥1; v=0 означает
supported, v=1 — contradicted, v=2 — insufficient_evidence. Hint — произвольная
дополнительная причина отбора, поэтому формализация не требует полноты graph selector.

```text
selected = hint OR NOT A₀ OR b₀+1 ≥ K
A₁ = if selected then (v = 0) else A₀
b₁ = if selected then 0 else b₀+1
selected AND v=0  ⇒  T₁
I(T,A,b,K) = (0 ≤ b < K) AND ((A AND NOT T) ⇒ b > 0)
```

Последнее условие перед I требует корректности только выбранных положительных
подтверждений. Значение v на пропущенном переходе не является выполненной
validation и не ограничивает истину: это неиспользованный символ формулы.

## Проверенные условия

Для каждой строки выполнены два запроса: SAT предпосылок и UNSAT предпосылок
вместе с отрицанием цели. Все шесть пар дали ожидаемый результат.

| Условие | Предпосылки и цель |
| --- | --- |
| initial_invariant | A₀=T₀=true, b₀=0, K≥1 ⇒ I₀ |
| transition_invariant | I₀ и обычный переход ⇒ I₁ |
| false_availability_requires_skip | I₀ и A₁=true, T₁=false ⇒ selected=false |
| unsafe_rank_increases | I₀ и ложная доступность на обоих концах ⇒ b₁=b₀+1 |
| exact_no_false_withholding | I₀, T₁=true и точная двоичная validation ⇒ A₁=true |
| tight_carry_template | K≥2, 1≤j<K, b₀=j−1, A₀=true, T₀=(j=1), T₁=false, hint=false ⇒ пропуск и b₁=j, A₁=true |

Первые два условия дают индуктивность I. При ложной доступности возраст положителен
и меньше K, а на каждом следующем ложно доступном состоянии возраст увеличивается
на единицу. Отдельный дискретный аргумент ограничивает серию K−1 состояниями.
Последняя строка задаёт шаблон достигающей границы истории для любого K≥2;
при K=1 инвариант исключает ложную доступность. Этот вывод объединяет результаты
решателя с явно изложенным аргументом по последовательности состояний.

## Примеры и контрпримеры

Ещё шесть SAT-запросов намеренно требуют конкретные состояния; во всех K=4.
Они показывают существенность предпосылок, а не частоту ошибок в проектах.

| Сценарий | Найденный переход |
| --- | --- |
| Неполный, положительно корректный validator | Истина=true; выбранный unknown скрывает запись, b: 0→0 |
| Ошибочный supported разрешён | На сроке ложная запись подтверждается и остаётся доступной, b: 3→0 |
| При unknown сохраняется доступность | На сроке ложная запись переносится, b: 3→0 |
| Срок с ошибкой на единицу | Ложная доступность переносится без проверки, b: 3→4 |
| Возраст сбрасывается при изменении исходника | Ложная доступность переносится, b: 2→1; нарушен рост ранга |
| Убрана проверка ранее недоступной записи | Истина восстанавливается, запись остаётся скрытой без проверки, b: 0→1 |

В последних трёх случаях validation не выбирается, поэтому показанный в raw model
символ v нельзя интерпретировать как выполненный вердикт. Циклы повторяющейся ошибки
для первых двух дефектных правил отдельно найдены в предыдущей конечной модели;
текущие SAT-запросы предъявляют нарушения одношаговых условий.

## Воспроизводимость и аудит

План закреплён в 2052627, runner — в e5ee97e. Использован Z3 4.16.0.0 в отдельном
окружении runs/smt-tools-20261104-v2; production dependencies не менялись. SHA-256
скачанного wheel совпал с официальными метаданными [PyPI](https://pypi.org/project/z3-solver/4.16.0.0/).
[Официальный репозиторий Z3](https://github.com/Z3Prover/z3) и
[руководство по SMT-LIB](https://microsoft.github.io/z3guide/docs/logic/intro/)
сохранены как источники инструмента; результаты CAMI получены локально.

Всего выполнено 18 solver checks: шесть UNSAT refutations, шесть SAT premises
и шесть SAT witnesses. Timeout, unknown, stderr или неожиданный статус считаются
ошибкой запуска. Проверены 57 artifact hashes и совпадение source snapshots.
Stdlib-аудитор повторно вычислил все 12 SAT transitions обычными Python-операциями.
Две подмены с пересчитанным manifest hash отклонены: неверная доступность и bool
вместо целочисленного verdict. Исходные результаты не менялись.

Proof objects сохранены, но не проверены независимым proof kernel. Доверительная
база включает правильность записи формул, Z3 и связь формальной модели с engine.
Непротиворечивость предпосылок не означает, что они выполнены в реальном проекте.
Исходная доступная запись предполагается истинной; рассматриваются завершённые
переходы с фиксированным claim и контрактом валидатора. Тайм-ауты потребителя,
публикация промежуточного состояния, wall-time гарантия и production resume
не доказаны. Фактических Docker executions и независимых человеческих labels
в этой проверке нет.

Материалы: reports/research-20261104/symbolic-audit-v1/. Каждую .smt2 формулу можно
выполнить закреплённым z3 бинарником. Полный повтор:

```sh
.venv/bin/python -m scripts.check_symbolic_audit \
  --solver runs/smt-tools-20261104-v2/bin/z3 --out runs/NEW_NAME
```

Отдельный аудит: `python3 scripts/audit_symbolic_witnesses.py RUN --out NEW_AUDIT.json`.
Окружение воспроизводится через requirements/smt.txt; точные wheel и binary hashes
зафиксированы в smt-environment.json и smt-wheel-audit.json.
