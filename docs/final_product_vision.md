В моей голове это вот так выглядит конечный продукт:

Например у юзера есть проект NextjsProject. Он хочет использовать нашу разработку CAMI для эффективной работы с ИИ, чтобы ИИ быстрее искал код и лучше ориентировался по коду, благодаря нашей разработке.

Он запускает скрипт который работает на фоне, допустим "cami run". Этот процесс на фоне постоянно работает и следит за файлами, и при изменении кода пересобирает нужные части связанного кода.

Потом, чтобы ИИ с которым он разрабатывает свой проект NextjsProject понимал что нужно использовать CAMI вместо встроенного tool find_code допустим, он в свой AGENTS.md кладет текст по типу:

"Don't use your tool for finding code. Instead, use CAMI via shell. Example: cami -f 'createUser'

it will give you dependency graph of that object/variable/function that is used in this project and where."

И используя CAMI то ИИ будет эффективнее понимать и искать код.

CAMI — не просто поиск по коду или граф зависимостей;

CAMI индексирует код и его связи, хранит знания о проекте и отслеживает изменения.
После правок CAMI обновляет затронутые части индекса и определяет, какие знания
нужно перепроверить, какие можно сохранить, а какие пометить как неопределённые.
ИИ-агент получает этот контекст через CLI, а в будущем — возможно через MCP.
