# Запуск задач с сохранением входов и расходов

Команда `cami task` запускает задачу через существующий локальный OpenCode и
автоматически сохраняет стартовый снимок, точный текст задания, внешний контекст,
ответы, наблюдаемые токены и проверенное решение. Нужны Linux, Python 3.12,
Git и работающий авторизованный локальный OpenCode 2.2.5.

Укажите корень Git-репозитория. Файлы задания и внешнего контекста можно хранить
вне него. Для проекта с исходниками под `src` выполните:

```sh
cami task \
  --workspace /path/to/project \
  --task-file /path/to/task.txt \
  --context-file /path/to/context.json \
  --grade-json '["python", "-B", "-m", "pytest", "-q", "-o", "pythonpath=src", "-p", "no:cacheprovider"]'
```

Замените тестовую команду на фиксированную проверку вашего проекта. Она выполняется
в сохранённой копии решения. Проверка должна импортировать эту копию, а не прежнюю
editable-установку, и не менять файлы артефакта. Временные файлы тестов создавайте
через `tmp_path` или вне проверяемого дерева. Запись Python bytecode отключена.

Внешний контекст должен описывать значимые входы вне репозитория: toolchain,
зависимости, внешние данные и проверку результата. Команда дополнительно фиксирует
модель, Python и хеши клиента и кода захвата. Она не обнаруживает изменения
необъявленных удалённых сервисов.

По умолчанию журналы находятся в `~/.local/state/cami-tasks/`. Каталог журнала
должен быть вне рабочего дерева. В выводе есть путь к записи, качество,
завершение исполнения, наблюдаемый расход и разрешение на обучение кеша.
Происхождение обычного запуска помечается `user`. Для проверок и экспериментов
задавайте `--origin admission` или `--origin experiment`.

Входной снимок использует строгий контракт `task_replay`: только обычные файлы,
не больше 64 MiB и 10 000 файлов, исключена только `.git`. Неподдерживаемый вход
отклоняется до вызова модели. Журналы содержат текст и исходники, поэтому хранятся
в приватном каталоге. Не добавляйте их в публичный репозиторий без проверки.

## Восстановление

После аварии выполните:

```sh
cami task recover --directory /path/to/journal
```

Восстановление проверяет сохранённую привязку, останавливает свою сессию и
сверяет, что запись относится к захваченному каталогу и модели. Затем получает
доступные ответы и проверяет сохранённое решение. Модель повторно не запускается.
Активный управляющий процесс блокирует восстановление, чтобы два исполнителя
не меняли один журнал одновременно. Повторное восстановление завершённой записи
возвращает прежний результат.

Качество и завершение исполнения независимы. Правильное решение сохраняется и
после ошибки. Потерянный usage остаётся неизвестным, известные компоненты доступны
отдельно. `known_subtotal` содержит нижние границы; `known_component_requests`
показывает, для скольких запросов известен каждый компонент. Эти поля сохраняются
и при ошибке провайдера, когда полного итога нет. Это не фактический счёт провайдера. Непрозрачные внутренние запросы
не считаются полностью покрытыми; обычная команда автоматически не обучает кеш.

## Подсчёт точных повторов

Из checkout CAMI выполните:

```sh
.venv/bin/python scripts/practical/summarize_task_journals.py \
  ~/.local/state/cami-tasks --out /path/to/repeats.json
```

Скрипт учитывает только записи с объявленным происхождением `user`, проверяет
стартовые снимки и строгие ключи. Он отдельно считает повтор задания и возможность
использовать уже завершённое проверенное решение. Admission и experiment
исключены. Пустая выборка имеет неопределённую долю, а не нулевую частоту.

The opt-in integrated pipeline is documented in [TASK_V2.md](TASK_V2.md).
`--mode legacy` remains the default; v2 state has separate worktree namespaces.
