# Аудит кода и протокола AI pilot v1

Проверены замороженный protocol, публичные rubric/schema и три скрипта. Ответы reviewer, каталоги `runs/blinded-ai-reviewer-*` и фактические результаты сравнения не читались. Замороженные файлы не менялись. Все воспроизведения используют новые синтетические данные.

## Подтверждённый пропуск распознавания module binding

**Серьёзность: блокирует утверждение о полном соответствии checker указанному rubric и его расширенное повторное использование. Влияние на текущие 36 случаев не установлено.**

Rubric требует `uncertain`, если целевое имя получает другое module-scope binding: `examples/ai_review_pilot/packet/rubric.md:16–20`. В `scripts/structural_checker.py:171–178` поиск `global` пропускает весь вложенный `ClassDef`. Поэтому такой исходник получает `supported`:

```python
def f():
    pass

class Outer:
    class Inner:
        global f
        f = 0
```

Объявление `global f` относит присваивание к module namespace. Это явно указанная в rubric причина отказа, хотя runtime binding в целом находится вне scope. Checker обнаруживает только одно определение `f`, не обнаруживает другое binding и проходит через `scripts/structural_checker.py:267–285` к `supported`.

Синтетическое воспроизведение сохранено в `synthetic_audit_results.json`, поле `nested_class_global`. Исполнялся только checker. Текст исследуемого модуля не исполнялся.

Не следует исправлять замороженный checker внутри v1. Сохранить исходный результат и известный пропуск. Исправление обхода вложенных классов требует отдельной версии checker и нового seal. Сравнение исправленного результата с v1 должно называться отдельным sensitivity analysis. Для текущего v1 можно отдельно проверить применимость находки к его источникам, не изменяя первоначальные решения.

## Форматные проверки не закрывают обязательный контракт review

**Серьёзность: пробел в проверке соблюдения протокола. Наличие фактического нарушения в ответах reviewer не оценивалось.**

Rubric требует конкретные извлечённые факты и отдельный `methodology.json`: `packet/rubric.md:43–55`. Schema разрешает произвольную непустую строку, объект или массив в `extracted_facts`; runtime-проверка делает то же: `scripts/validate_ai_review.py:155–158`. Объект `{"placeholder": true}` проходит форматный аудит без требуемых фактов. Синтетическая проверка также проходит при отсутствии methodology sidecar.

Это согласуется с явно ограниченной ролью format validator. Но `scripts/analyze_ai_pilot.py:118–124` использует только такой аудит и копирует каталог, не проверяя обязательный sidecar или наличие требуемых фактов. Статус `complete` анализа поэтому не является свидетельством соблюдения rubric.

Для отчёта v1 координатору нужно отдельно проверить существующие sidecars и обязательные факты, сохранив исходные ответы. В будущей версии можно добавить проверку их структуры и hashes. Не следует заполнять отсутствующие факты за reviewer или переименовывать постфактум созданный sidecar в первоначальную запись методологии. Координатор сообщил, что обе фактические sidecar существуют; этот аудит их не читал.

## Счётчики и ограничения измерения

В рассмотренном анализаторе не найдена ошибка, которая удаляет неопределённые случаи из знаменателя. `keyed` требует точного полного набора ID; private map должен совпасть с ним. Каждый случай попадает в comparisons, включая `uncertain`: `scripts/analyze_ai_pilot.py:30–63`. Проверяется итоговый знаменатель 36: строки 131–133. Отдельно считаются расхождения AI, расхождения с mechanical reference и ошибки контролей: строки 65–83. Ожидаемый `uncertain` у duplicate-контроля считается unresolved, но не control failure. Это допустимо, если эти разные показатели так и объясняются в отчёте.

Остаются ограничения:

- Distinct `agent_task` проверяет разные заявленные строки, а не реальные изолированные контексты. Проверить реальные контексты может только координатор по истории запуска.
- Все методы могут разделять ошибки CPython и одинаковой модели. Согласие не подтверждает истинность или независимость.
- `packet_sha256` в `validate_ai_review.py:116–124` включает cases и источники, но не rubric/schema. Координатор проверяет rubric/schema через общий seal. Hash в reviewer record нельзя описывать как hash всех инструкций reviewer.
- Контроли с новым случайным именем или параметром проверяют простые отрицательные случаи. Они не измеряют частоту ошибок на сложных реалистичных изменениях.
- Три parent-группы и повторяющиеся модули дают зависимые наблюдения. 36 строк не являются 36 независимыми задачами.
- Parent agreement не доказывает сохранение того же predicate при переходах. Для переноса на carry/closure нужна отдельно замороженная проверка изменений и правил отбора.

## Уточнение гипотезы о carry

Простое добавление `f = 0` после определения по чтению production-кода уже обнаруживается: `src/cami/index.py:244–250` помечает определение ambiguous, `compare_indexes` включает ambiguous node в изменившиеся символы на строках 311–315, а production validator отказывает на `src/cami/validation.py:44–45`. Поэтому эта конкретная гипотеза не подтверждена кодом. Production эксперимент в этом аудите не выполнялся.

Вложенный класс с `global f` представляет более содержательный синтетический случай для отдельного эксперимента. В production parser присваивания внутри класса получают qualified prefix, а независимый checker имеет подтверждённый выше пропуск. Их возможное согласие само по себе также не докажет корректность. Фактический production outcome здесь не вычислялся.

## Воспроизведение

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python runs/ai-pilot-audit-development-20261104/reproduce_findings.py
```

Скрипт читает только проверяемые реализации и создаёт временный синтетический пакет под каталогом аудита. После проверки временный пакет удаляется. `synthetic_audit_results.json` содержит hashes проверенных реализаций и оба наблюдения. Это результаты аудита кода, а не ответы reviewer, labels или receipts.

Прямой запуск `python scripts/analyze_ai_pilot.py` не поддерживает package import в текущем окружении. Координатор использует документированный запуск `python -m scripts.analyze_ai_pilot`; поэтому это не считается блокирующей находкой.
