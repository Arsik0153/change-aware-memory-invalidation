# Воспроизведение проверки

## Проверка сохранённых результатов без модели

Из корня репозитория выполните:

```sh
.venv/bin/python scripts/practical/analyze_new_study.py
.venv/bin/python scripts/practical/check_installed_task.py
.venv/bin/pytest -q tests/test_task_session.py tests/test_task_recovery.py tests/test_practical_output_contract.py tests/test_opencode_task_entrypoint.py tests/test_task_journal_summary.py tests/test_practical_fixture_inventory.py
```

Аудит проверяет расписание, SQLite, исходники оценённого решения, исходные входы,
фиксированные тесты, хеши артефактов, модель, составляющие токенов и решение
по заранее записанному правилу. Он не обращается к провайдеру.

`model-summary.json` содержит таблицу по задачам. `model-audit.json` содержит
хеши терминальных записей. Протокол находится в `protocol.json`, его хеш
находится в `protocol-seal.json`. Начальная редакция до добавления нижнего
порога качества сохранена как `protocol-prelaunch-v1.json`. Изменение сделано
до создания каталога модельного прогона.

## Окружение

Базовый образ восстановлен из
`output/opencode-runtime-v2-20261104/cami-opencode-runtime-v2.tar`.
Его идентичность:
`sha256:3e5f5aee66022082251b8cc1fb5c3ea9399ec9589ab98ba3d190a8b0ab46b387`.

Новый образ добавляет закреплённые urllib3, certifi, charset-normalizer и idna.
Dockerfile и оба журнала сборки находятся в
`runs/practical-complete-20261115/runtime/`.
Первый build не распознал локальный digest в FROM как локальный образ.
Повторная сборка использует локальный тег с отдельно проверенным базовым digest.
Фактическая идентичность нового образа закреплена в `runtime-manifest.json`.

`frozen-source.tar.xz` сохраняет исходники и зависимости экспериментального кода
в момент запуска. Поздние исправления упаковки команды не меняют выполненный
модельный эксперимент.

`output/practical-complete-20261115/runtime.tar.gz` сохраняет готовый новый
образ. Его можно загрузить командой `docker load -i` и сверить digest с манифестом.
`raw-evidence.tar.xz` сохраняет все модельные попытки, исходники задач, admission,
журналы сборки и финальную wheel-сборку. `final-source.tar.xz` содержит более
поздний код обычного запуска с исправлением частичного usage и восстановлением.
Хеши архивов находятся в `completion-manifest.json`.

Для общей проверки зависимостей и проекта:

```sh
uv sync --locked --extra dev --extra llm
uv run pytest -q -m 'not docker'
docker build --network=none -f runs/practical-complete-20261115/runtime/Dockerfile.probes -t cami-practical-probes:20261115 runs/practical-complete-20261115/runtime
CAMI_TEST_IMAGE=cami-practical-probes@sha256:6ed576eca85e3817e5bdf08b043db442b98d94e8e0ad0547fafbe83fd08d3a28 uv run pytest -q -m docker
```

При первой общей проверке в локальном окружении отсутствовал закреплённый
`tiktoken`: 1801 тест прошёл, 12 завершились ошибкой подготовки. После установки
все 12 прошли. Общий финальный прогон использует зависимости из `uv.lock`.
Оба журнала сохранены.

Для четырёх существующих Docker-тестов создан отдельный образ с теми же слоями,
но без OpenCode entrypoint. Они запускают Python напрямую и требуют имя вида
`repository@sha256:...`; первоначальная передача только image ID была отвергнута
валидацией ещё до запуска контейнера. Этот журнал также сохранён. Основной образ
и все модельные измерения не менялись.

Исходное описание таймера указывало границу после устойчивой терминальной записи.
Выполненный код останавливал таймер перед её публикацией. Отдельный
`publication-tail-audit.json` сохраняет проверяемые границы этого интервала;
протокол, наблюдения и критерий решения не изменены. Исправлен только текст
генератора будущих протоколов, после завершения всех 72 сессий.

## Новый модельный прогон

Используйте отдельную копию репозитория без каталогов этого прогона.
Сохранённые попытки не удаляйте и не перезаписывайте.

```sh
.venv/bin/python scripts/practical/prepare_new_tasks.py
.venv/bin/python scripts/practical/new_study.py admission
.venv/bin/python scripts/practical/new_study.py freeze
.venv/bin/python scripts/practical/new_study.py run
.venv/bin/python scripts/practical/analyze_new_study.py
```

Подготовка требует доступной Git-истории в `data/corpora/click`,
`data/corpora/requests`, `data/corpora/packaging-development-v1`.
`run` выполняет до 72 потенциально платных модельных сессий через существующий
локальный OpenCode. Это повторение протокола с новыми наблюдениями, а не
детерминированное восстановление прежних ответов модели.

Исполнитель пропускает только полностью завершённые попытки. Каталог начатой
попытки без терминального результата блокирует повторный запуск модели.

## Локальный поиск

`local-comparison-v2` сохраняет отдельный опыт с ошибочным ожиданием exit 1
для отсутствующего символа. Контракт требует exit 0. `local-comparison-v3`
содержит новый опыт после исправления этого ожидания. Результаты первого
опыта не исправлялись задним числом.

В каждой версии 50 измеряемых запусков: пять пар для справки и четырёх видов
поиска. Для тёплого индекса перед измерением выполняется отдельный запуск
подготовки. Полное время холодного запроса включает построение индекса.
В обоих вариантах сохраняются чтение файлов и проверка актуальности.

Различия observation и двух идентификаторов реализации проверяет
`scripts/practical/output_contract.py`. `snapshot_id`, режимы покрытия,
совпадения и все остальные семантические поля сохраняются в сравнении.

При сверке входов аудит воспроизводит тот же `shutil.copytree`, что и закреплённый исполнитель. Две внутренние ссылки на сертификаты Requests становятся обычными файлами при подготовке каждого рабочего дерева. Аудит сверяет все получившиеся байты и режимы, а ссылки за пределы канонического fixture отвергает. Исходный архив и попытки остаются неизменными.

`publication-receipts.tar` дополнительно сохраняет те же 72 терминальные записи в формате PAX с наносекундными mtime для аудита границы таймера. После распаковки raw-evidence распакуйте этот небольшой архив поверх него: содержимое записей идентично, восстанавливается точность метаданных времени.
