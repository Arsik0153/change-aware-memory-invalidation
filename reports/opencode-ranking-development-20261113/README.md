Both memory conditions use readable display, the same 329-record source catalog
and independent persistent memory namespaces. Each follows the fixed canonical

strictly lower four-stage total noncached normalized token work **and** native

complete and uniform complete provider tier. Plain is descriptive context.
Wall totals are descriptive. No retries, replacement sessions, extensions,
heldout calls or pooling with historical blocks. This dependent development
block cannot establish population superiority. Exact rules are in protocol.json.

recognized read errors, before publication redaction. It stores counts and IDs
without text or credentials. Unsupported errors and incomplete exports remain
unknown. Version1 and the closed format report keep their original semantics.

acceptance/regression tests. There were **zero retries**. All token, native-read,
ranking identity and provider-tier gates are complete. Every provider response
reported `default` although `priority` was requested; this is not priority-speed
evidence. The frozen criterion is **not met**: both primary totals increased.

## Post-hoc diagnosis, separate from the decision

The unchanged ranker was replayed against all eight observed memory queries at
their original limit and byte ceiling. The recorded policy reproduced every
observed selected set and relative returned/withheld order. Switching policies
changes selected records in two queries and order in five. The candidate includes
`help_option` in both queries where lexical ranking omits it; nine explicit-symbol
observations have zero candidate omissions. Thus the narrow retrieval correction
occurred, but it did not establish agent efficiency.

Both CAMI conditions made four successful memory calls (limit 5), returned sixteen
record observations and withheld four. Native read calls were 46 lexical versus 59
identifier. Six candidate record observations were truncated, versus five lexical.
The largest difference was stage 2: +11,147 token work and +28,848 read bytes.
Stages 1/3/4 contributed +3,540/-2,700/+1,278 tokens and +5,170/-2,039/+1,980 bytes.
These are dependent observations, not separate statistical replications.

On stage 2 the candidate made 20 reads versus 13 lexical. Seven source reads in each
returned 39,536 versus 25,768 bytes. Test reads were 7 versus 2 and returned 20,459
versus 6,745 bytes. Additional context acquisition is observed; the artifacts do
not prove why the model chose it or that any individual read was avoidable.
The candidate's stage 2 memory returned complete (untruncated) definitions of
`Command.get_help_option`, `help_option` and `Command.get_help_option_names`.
Therefore, missing or truncated `help_option` is not an evidenced explanation
for its extra reads in that session. The different model-generated queries also
selected different surrounding methods; there is no paired causal decomposition
of query choice, ranking order, response content and subsequent agent behavior.
The next audit must consider the information needed around a retrieved symbol,
not assume that a longer copy of that same symbol will help.

Backend lookup spans were below 1% of inclusive session time in both conditions;
these nested spans exclude RPC/trace append and are not additional charged costs.

`diagnostics.json` and `query-replay.json` are explicitly post-hoc. The path
extractor now recognizes OpenCode 2.2.5's `input.path`; the earlier diagnostic
helper only looked for `filePath` and therefore reported null paths. This repair
does not alter the frozen primary byte endpoint or any historical decision.

## Updated next work

1. Keep lexical ranking as the baseline. Close this block with its negative
   result; do not extend it or change its thresholds.
2. Audit whether returned source prefixes contain enough information for the
   next concrete edit, using the preserved calls and read ranges. Separate
   missing records, truncated records, stale/withheld records and voluntary
   verification. Do not equate overlap with an avoided read or infer model intent.
3. Before another paid block, require a generic, authored case in which a
   proposed memory response provides the necessary current information within
   a fixed byte budget while retaining invalidation semantics. Correct symbol
   ranking alone no longer justifies a resource-saving hypothesis.
4. Freeze a new protocol only for a materially different supported intervention,
   with fresh development tasks before making a general utility claim. Leave
   heldout data unopened and keep this block separate.
