# Common readable projection — verified, not wired

Only `integrations/opencode/readable_response.py` and its focused authored test file are added. There is no adapter/default/CLI/controller/harness/analysis wiring. Existing full and compact behavior is untouched.

`readable_result(full_result)` accepts the existing single-text JSON-object backend MCP contract. For nonempty homogeneous known literal records it emits `research-memory-readable/1`: ordinary Markdown fences, a canonical JSON shared header, per-record JSON metadata and exact Python prefix text. Essential identity, entire subject/span, prefix/truncation, label/availability/optional state, freshness/counts/selection budget and entire withheld summaries are copied exactly. Literal kind/format are shared. Query echo and original provenance/schema markers stay in the unchanged full audit result. No requested limit is synthesized from trace data.

The shared header contains a **new** `audit_receipt`. As in compact/1, construct the base display without this field, hash its complete MCP result, hash `{format, full_result_sha256, projection_result_sha256}`, then render the final display with that receipt. Audit `model_result_sha256` independently binds the complete final model result including its embedded receipt. The receipt therefore distinguishes otherwise identical displays backed by different provenance/readsets. It is SHA integrity, not a signature or validation oracle. Independent reconstruction removes only the canonical header audit field and preserves all remaining physical source bytes.

Empty, withheld-only, mixed, error, unknown schema/fields, unrecognized literal tuple/source, and raw source control bytes delegate to `compact_result(full_result)`. The resulting model bytes and original compact receipt are identical; only audit metadata adds requested format, effective format and a bounded reason. No unsupported case invents a current claim or changes query/ranking/payload/availability. As with compact_result, malformed inputs outside the backend MCP JSON-object contract are not an additional transport parser API.

Focused tests independently parse ordinary fences and compare exact fields/physical bytes, verify the new two-phase receipt and final-result digest, mutate claims/provenance/error status/receipt, check distinct origin bindings, and compare fallback model bytes+receipt with unchanged compact_result. `replay_packets.py` is an explicit offline runner for all24 sealed v6 calls and is not a normal test or a model study.

Initial/final packet model/audit artifacts are byte-identical; a final extra authored unknown-backend-type guard affects no original packet. `verification-summary.json` and `packets-final/report.json` bind the final source. No full suite, Docker, models or wiring was run. The frozen exploratory prototype under `runs/opencode-readable-projection-prototype-20261106` remains untouched. The earlier20-session proposal remains unselected and unexecuted.

The actual complete final display is hash-bound by audit.model_result_sha256. The embedded receipt binds the unchanged full result and the receipt-free base display, not a self-referential final hash. Different provenance changes the embedded receipt even if all other visible fields are identical. Fallback receipt payloads remain compact/1 without any rewrite.
