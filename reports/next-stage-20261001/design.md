# Выбранная структура изменений

## Ground

engine.check_inputs получает конфигурацию, claims, provenance и parent receipts. Policy видит SelectionContext с изменениями и предыдущим состоянием. Validator получает отдельный ValidationContext без ID policy и без labels. После выбора engine записывает события и обновляет MemoryState. Scorer отдельно читает labels.

index.build_index создаёт consumer-to-dependency рёбра. compare_indexes объединяет старые и новые рёбра. policies.select_claims сначала расширяет поддержку claim, затем проверяет неизвестные узлы и обратное влияние изменений. Module-level unresolved импорт превращает Node(path, null) в причину проверки всех claims с этим path. File policies не строят граф и используют общий fallback.

## Sketch

Рассмотрены два варианта для точного синтаксического правила.

1. Дополнительное поле PolicyConfig.structural_scope и ограничение по protocol_version. Оно позволяет оба варианта внутри одной версии, но расширяет старые defaults, меняет hashes sealed конфигураций и требует обновить идентичность policy в scorer.
2. SelectionContext.protocol_version с прежним default 1.0. Версия 1.1 однозначно определяет суженное правило. Сравнения идут отдельными dataset, смешение протоколов scorer отклоняет.

Выбран вариант 2. Старые JSON-конфигурации и seals не получают новые defaults. Это development-абляция нового протокола, а не скрытая оптимизация 1.0.

Claim остаётся неизменяемым. Selection содержит причины выбора. ValidationResult содержит проверенный verdict. Структурный claim без явных зависимостей в 1.1 использует прямые AST changes и заданные anchors. При явных зависимостях сохраняется полный консервативный обход. Неполнота provenance и parse limitations продолжают выбирать проверку. Для behavioral/prose сохраняется исходный механизм.

## Implement

Исправления неоднозначных binding и неизвестных global reads находятся в индексаторе. Версии INDEX_VERSION и VALIDATOR_VERSION повышены до 2, чтобы старые результаты не получали новый смысл через кеш. Состояния и формулы качества не меняются.

Полное время engine хранится в manifest отдельно от phase costs. Оно включает публикацию артефактов и hashes. Последняя запись самого поля измерения не входит в этот интервал и явно названы. Benchmark дополнительно измеряет полный процесс, включая эту запись и запуск Python. Восстановленная стоимость кеша остаётся оценкой.

## Agree и Scrap

Пользователь разрешил обычные технические решения без подтверждения. Новая архитектура сервисов не нужна. Причин отказываться от существующих Claim, Provenance, Selection и MemoryState нет. Отдельный сборщик данных не связан с execution engine и не создаёт labels.

Дизайн проверяли агенты Codex Sol high. Других семейств моделей не использовали согласно пользовательскому ограничению.
