## Что сказать руководителю

Идея состоит в том, чтобы агент сохранял знания о репозитории, но перепроверял их после изменений кода. Изменившийся файл ещё не означает, что каждое связанное с ним утверждение стало неверным. Поэтому сначала система выбирает утверждения для проверки по их источникам и зависимостям, затем отдельно проверяет их истинность. Эксперимент измеряет стоимость этой процедуры, ошибочное удаление полезных знаний и пропуски устаревших утверждений.

Короткое объяснение по-английски:

> I would like to study how coding agents can maintain repository memory as the code evolves. My proposed system will use provenance and code changes to select memories for revalidation, then check whether each selected claim still holds. I will compare it with revalidating every claim using the same validator. The main contribution I want to evaluate is the cost and reliability of maintaining memory across successive revisions, especially when provenance is incomplete.

## Как объяснить отличие от близкой работы

В план включён свежий preprint Atul Anand, *Impact Is Not Invalidation: Ask About the Claim, Not the Diff*, от 20 сентября 2026 года. Он непосредственно связан с темой, поэтому не стоит заявлять, что проверка конкретного утверждения сама по себе является новой идеей.

Предлагаемое продолжение — последовательное поддержание памяти через несколько версий, учёт стоимости хранения и обновления provenance, проверка поведения при неполных связях с источниками. Сравнение с перепроверкой всей памяти использует один и тот же validator. Эти отличия являются исследовательским планом; их достаточность для диссертации нужно согласовать с руководителем.

Источник: [preprint Anand](https://arxiv.org/abs/2609.25130).

## Порядок подачи

1. Открой DOCX или PDF и распечатай план для руководителя. Получи согласование окончательного текста, подпись или печать и фактическую дату. Если руководитель внесёт содержательные изменения, сначала обнови документ, затем получи подпись под окончательной версией.
2. Следуй отдельному указанию кафедры о согласовании с 주임교수 강동완. В письме сказано, что после подтверждения руководителя кафедра организует общее согласование. Имя 강동완 уже внесено в строку документа; подпись остаётся пустой. Подпись руководителя сама по себе не подтверждает завершение этого этапа.
3. В SUIS открой `학사 → 졸업 → 논문 → 등록_논문연구계획서`.
4. Введи окончательно согласованные корейское и английское названия. Текст для копирования приведён ниже.
5. Проверь скачиваемую форму и требования к загрузке. Загрузить нужно окончательный согласованный файл, с подтверждениями в требуемом кафедрой виде. DOCX из пакета не содержит подписей; PDF также пока не подписан.
6. Нажми `저장` только после проверки названий, файла и согласований. После сохранения проверь запись и имя вложения; при возможности открой или скачай загруженный файл. Сохрани подтверждение подачи.
